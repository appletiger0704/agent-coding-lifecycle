# v0.4 RC — Quick versus Tracked

## Quick (explicit only)

Use for small, reversible, local script changes and routine bugfixes when the
project does not require an Issue or PR. Example:

```text
$agent-coding-lifecycle quick 修正這個 Python 腳本的錯誤
/agent-coding-lifecycle:quick 修正這個 Python 腳本的錯誤
```

Check git worktree, respect existing changes, follow repo-specific tests, and report
what was actually run. No silent remote writes, architecture overrides, or deployment.
If scope expands into public API, security/data contracts, major components, or durable
cross-session work, stop and propose Tracked.

## Tracked (explicit Issue number)

For new features or Codex ↔ Claude Code handoff:

```text
$agent-coding-lifecycle run 請接續 Issue #123
/agent-coding-lifecycle:run 請接續 Issue #123
```

Prerequisites: Git checkout with a verified local default branch, `gh` authentication,
`.agent-lifecycle/issues/123.json` with branch and task type. A missing or outdated
local default branch requires **manual** `git fetch`/reconciliation; status does not mutate refs.
Every transition remains scoped to a single Issue. Use the Issue contract for relevant
OpenSpec change and ADR links; do not rely on chat history or a handoff file alone.

## Verification profile

Copy `templates/verification.python.json` to the product repo's
`.agent-lifecycle/verification.json`, review argv commands and installed tooling,
then call the installed runner with `--list` followed by `--run` as appropriate.
The runner does **not** use a shell, persist output, or install requirements.
If the project lacks `uv`/`ruff`/`pytest`, adapt the profile rather than fabricating success.

## Version checks

```bash
bash agent-coding-lifecycle/scripts/install.sh /path/to/product --check
bash agent-coding-lifecycle/scripts/install.sh /path/to/product --dry-run
bash agent-coding-lifecycle/scripts/install.sh /path/to/product --force
```

`--check` is read-only and fails on missing or different files. `--force`
overwrites managed Skill and Claude wrapper copies after you review the diff.
Check-in per-project copies if reproducibility matters; the central repo is not
automatically synchronized with every product repo.

## Handoff

Use `templates/handoff.example.json` as an optional, concise record in PR/Issue.
It is always `source=handoff_unverified`; the next Agent **must** refresh authoritative
GitHub/Git/CI/ADR evidence before acting. Never store secrets or personal data.
